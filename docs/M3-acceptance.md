# M3 技术亮点 · 验收记录

> 环境：JDK 17 / Spring Boot 3.3.13 / MyBatis-Plus 3.5.7 / Redisson 3.35.0 / MySQL 8.0.46 / Redis 5.0.14.1
> 方式：跳过测试打包，以独立实例（端口 18080、18081）拉起，纯接口调用，不依赖 IDE
> 日期：2026-10-12 ~ 2026-10-14

## 一、验收范围

M3 一共九条亮点，每条都按「先量基线 → 再改 → 再量」的方式验收，**没有实测数据的不算通过**。

重点不是"功能能跑"，而是：

1. 加之前 / 加之后各有一组可比数据；
2. 并发的判据以**回库计数**为准，不看返回码；
3. 每条都写清**已知局限**，不假装没有问题。

## 二、九条亮点与对比数据

### M3-1 乐观锁 + 用户维度唯一索引

要解决的问题：唯一索引只能表达"某组值必须唯一"，表达不了"每人每时段最多 1 个座"这种**数量约束**。
同一个用户并发抢两个不同座位时，两条记录都合法，唯一索引拦不住。

| 阶段 | 探针 | 返回分布 | 回库计数 |
|---|---|---|---|
| 加乐观锁**之前** | 同一 token 并发抢两个不同座位 | 2 单**全部成功** | 2 |
| 加**之后** | 同上 | 1×`200` + 1×`1016`（重试耗尽） | **1** |
| 回归 | 20 个不同用户抢同一座位 | 19×`1001` + 1×`200`（128 ms） | **1** |

并发拦下的是 `1016` 而不是 `1015` —— 乐观锁是「检测冲突 + 重试」，不是「排队等待」。
这正是 M3-2 引入分布式锁的动机。

### M3-2 手写 Redis 分布式锁

`RedisLockUtil`：`SETNX` 一条命令完成加锁 + 过期，UUID 标识持有者，Lua 脚本释放，自旋等待。
关键是**锁在外、事务在内**（用 `TransactionTemplate` 而不是 `@Transactional`）——
否则 unlock 会发生在事务提交之前，存在「锁已释放、数据未提交」的窗口。

| 探针 | 返回分布 | 回库计数 |
|---|---|---|
| **跨实例**并发抢两个不同座位（8080 + 18080） | 1×`200` + 1×`1015` | **1** |

验证手法：在「事务内、锁内」插一段 sleep 制造长耗时窗口 —— 窗口在锁外时返回 `1016`，
移进事务后返回 `1015`，即"锁确实包住了事务"。

### M3-3 换 Redisson（保留手写实现做对比）

| 阶段 | 探针 | 返回分布 | 回库计数 |
|---|---|---|---|
| M3-2 手写锁 | 跨实例并发抢两个不同座位 | 1×`200` + 1×`1015` | **1** |
| M3-3 Redisson | 同上 | **1×`200` + 1×`1015`** | **1** |

数字一样才是对的：换实现不该改变行为。手写实现 `RedisLockUtil` 保留在仓库里作为对照组。

**看门狗实测**（业务里插 `Thread.sleep(20000)`，让它超过锁的默认 30 秒周期）：

```
t=2s    TTL=28s   type=hash
t=8s    TTL=22s
t=10s   TTL=30s   ← 从 22 跳回 30：看门狗续期
t=20s   锁消失（业务结束，正常释放）
```

锁的类型是 `hash` —— 这正是它和手写锁（`string`）不能共用同一个 key 的原因。

### M3-4 ZSet 延时队列

`key: delay:checkin`，`member: reservationId`，`score: deadline 毫秒时间戳`。

- 下单成功后（`afterCommit`）写入；取消 / 签到时摘除
- 定时任务每 30 秒扫一次，「取 + 删」用一条 Lua 合成，避免两个实例领到同一批 id
- 处理单条时带 `status = 1 AND occupy_flag = 1`，保证幂等

| 项 | 实测 |
|---|---|
| ZSet 里的 score == 库里 deadline 毫秒 | `1796106000000` == `1796106000000` |
| 取消后 | 立刻从 ZSet 消失 |
| 手工把 deadline 挪到 10 分钟前 | 任务 **20 秒内**扫到；`status=5`、`occupy_flag=NULL`、ZSet 无残留 |
| 同样条件再执行一次 | 影响 **0 行**，状态不再变化 |

### M3-5 座位可用性缓存（穿透 / 击穿 / 雪崩）

缓存的是**查询结果**（某自习室某天某时段的可用座位列表），不是座位实体。

| 路径 | 平均耗时 | P95 | **数据库被查次数**（200 次请求） |
|---|---|---|---|
| 不加缓存（每次回源） | 2.8 ms | 3.1 ms | **200** |
| 加缓存后（命中） | 1.2 ms | 1.3 ms | **0** |

> 耗时只差 1 毫秒，因为本地 MySQL 本来就快。缓存的收益在"数据库被查几次"，
> 所以这条的判据是查库次数（`log-impl=StdOutImpl` + `grep -c "Preparing:"`），不是耗时。

| 问题 | 场景 | 实测 |
|---|---|---|
| 穿透 | 不存在的 roomId 连打 100 次 | 数据库被查 **1** 次（空值缓存 TTL 60 秒） |
| 击穿 | `DEL` 热点 key 后 20 线程同时打 | 数据库被查 **1** 次 |
| 雪崩 | 同时建 10 个 key | TTL 打散在 366 ~ 413 秒 |

### M3-6 缓存一致性（Cache Aside + 延迟双删）

写操作只删缓存、不更新缓存；删除时机在**事务提交之后**（`afterCommit`），
覆盖下单 / 取消 / 超时释放三条路径；删除后 500 ms 再删一次。

| 项 | 实测 |
|---|---|
| 核心时序 | 下单后缓存 key **立刻消失**、立刻查空座座位即消失；取消后立刻恢复 |
| 延迟双删 | 下单后手工把旧值写回缓存（模拟"慢半拍的回填"），700 ms 后再看已被第二次删除清掉 |
| 超时释放路径 | 任务释放座位后缓存被清、立刻查空座座位已可见 |
| 并发压力 | 25 秒内写入 1054 次 / 查询 20636 次、0 失败；停止后无脏值残留，回源内容与库完全一致 |

### M3-7 热门座位排行

按 `roomId` 分 key 的 ZSet，`member = seatId`、`score = 被预约次数`，计分在下单 `afterCommit` 里。

| 项 | 实测 |
|---|---|
| 同一座位连订 3 次（每次取消后再订） | score 1 → 2 → 3（**取消不扣分**） |
| 再订 B 两次、C 一次 | `ZREVRANGE` 顺序 A(3) > B(2) > C(1) |
| 失败的单 | 第 4 次订 A 成功（score→4），紧接着重复预约返回 `1015`，score **仍为 4** —— 被拒的单不计分 |

### M3-8 预约接口限流（Lua 令牌桶）

桶参数：容量 10，补充速率 5 个/秒，key = `rate:reserve:user:{userId}`。

| 项 | 实测 |
|---|---|
| 桶容量 | 顺序快打 13 次共 147 ms → 前 **10** 次全部放行，第 11 次起 `1017`；放行数与理论值「容量 10 + 期间回血 0.7」吻合 |
| 桶见底 | 紧接着再打 5 次 → 5 个全是 `1017` |
| 按速率回血 | 停 1 秒后连打 8 次 → 放行 6 个（1 秒回血 5 个 + 残余），之后重新开始拦 |
| **突发** | 停 3 秒攒满后并行打 10 次 → **一个 `1017` 都没有** |
| 空闲释放内存 | 桶 key 的 TTL = 4 秒 |
| 按用户隔离 | A 被限流返回 `1017` 时，B 用同一个「日期+时段」仍能正常下单 |

### M3-9 幂等防重复提交

一次性提交令牌 + `SETNX` 消费，令牌由服务端签发并与当前登录用户绑定。

```
GET  /reservation/token                       签发令牌（与当前用户绑定，5 分钟）
POST /reservation  + Idempotent-Token 头      消费令牌，重复提交返回 1006
```

「签发记录」与「消费标记」是两个 key：消费标记在业务失败时删掉（归还令牌、允许换座位重试），
签发记录留着不删 —— 否则重试时就分不清手里的令牌是伪造的、还是刚被归还的。

| 项 | 实测 |
|---|---|
| 同一令牌连打两次 | 第一次 `200`、第二次 `1006`；库里只有 1 条记录 |
| 换令牌 + 换组合 | `200`（令牌是一次性的，不是一次性账号） |
| 业务失败归还令牌 | 令牌撞 `1015` 后消费标记 `EXISTS` 变 0、签发记录仍在 → **同一个令牌**换组合重试 `200` |
| 并发同一个令牌 | `[200, 1006]`，落库总数 **1** |
| 客户端自己造的串 | `1006`（服务端没有签发记录） |
| 令牌归属 | B 的令牌给 A 用 → `1006`；B 自己用 → `200` |
| 不带 / 空串 / 纯空格令牌 | 都是 `1006` |

## 四、复现方式

### Postman

导入 `postman/CampusBook.postman_collection.json`，按目录顺序执行即可：

```
01 准备        健康检查 → 注册 → 登录（自动保存 token）
02 管理端      新增自习室 → 自习室列表（自动取 roomId）→ 批量生成座位 → 座位分页
03 预约闭环    查空座（自动取 seatId）→ 获取幂等令牌 → 下单（自动保存 reservationId）
               → 我的预约 → 签到 → 取消 → 再查空座 → 热门座位排行
```

`token` / `roomId` / `seatId` / `reservationId` / `idempotentToken` 都由脚本自动串联，
预约日期由 pre-request 脚本动态生成，不需要手工改变量。

### 命令行

```bash
DATE=2026-10-16 SLOT=2 bash _accept.sh        # 端到端闭环

node _loadtest.js /tmp/tokens.txt <seatId> <date> <slotId>          # N 个用户并发抢同一座位
node _gap-test.js   <token> <seat1> <seat2> <date> <slotId>         # 同实例缝隙探针

URL_A=http://localhost:18081/reservation URL_B=http://localhost:18080/reservation \
  node _gap-cross.js <token> <seat1> <seat2> <date> <slotId>        # 跨实例缝隙探针
```

M3-9 起下单必须带 `Idempotent-Token`，三个脚本都会先向 `/reservation/token` 取令牌。

## 五、已知局限

- **延迟双删依赖经验假设**：靠"500 ms 足以覆盖绝大多数慢查询"兜住并发场景下慢半拍的回填，
  不是数学保证。更强的方案是给缓存加版本号、或订阅 binlog 异步失效，本项目未采用。
- **乐观锁的 CAS 粒度偏粗**：CAS 的目标是整行 `sys_user`，而它要保护的不变量只是
  「同一用户 + 同一天 + 同一时段最多 1 个座」。因此同一个用户**并发发起多个不同时段**的下单
  也会在 `sys_user.version` 上互相撞，`MAX_RETRY = 3` 在 10 路并发下不够用。
  正常单击不会遇到。
- **排行榜只在 Redis 里**，重启会丢。它属于统计类数据，生产环境应定时落库或直接以数据库为权威源。
- **限流只有一个维度**：按「用户 + 接口」，没有全局或 IP 维度的兜底。
- **令牌 5 分钟内只能成功提交一次**：前端若固定复用一个令牌，会连续拿到 1006。
- 签到时间窗口的前后分钟数为固定值，尚未做成配置项。

## 六、本次验收中发现并修复的问题

| 现象 | 根因 |
|---|---|
| 缓存一上线，查空座接口全 500 | `new GenericJackson2JsonRedisSerializer()` 内部是裸 `ObjectMapper`，没注册 `JavaTimeModule`。此前只往 Redis 存登录态的字符串与数字，一直没暴露；一开始缓存带 `LocalDateTime` 的实体就抛 `InvalidDefinitionException` |
| 超时释放座位后，接口最长 7 分钟看不到它 | 删除缓存的路径漏了「定时任务释放座位」这一条。缓存 TTL 是 300~420 秒，靠自然过期自愈太慢 |
| 参数类型错误 / 缺少必填参数 / 路径不存在，一律返回 500 | 都被兜底的 `@ExceptionHandler(Exception.class)` 接走了，把 4xx 吞成了 5xx。其中"路径不存在"是 Spring 6.1 起的 `NoResourceFoundException` |
| 同一个 key 上加两把锁报 `WRONGTYPE` | 手写锁用 `SETNX` 存 String，Redisson 存 Hash，数据结构不同，不能共用 key |
| Spring 组件内部 `NullPointerException` | 手动 `new` 了容器管理的组件，注解注入不生效。同类问题在 `RedisLockUtil`、`RedissonConfig` 上各出现过一次 |
| 释放类操作返回 200，但字段没变 | MyBatis-Plus 的 `updateById` 默认 `NOT_NULL` 策略，null 字段被静默跳过。想写 NULL 必须显式声明字段策略 |
| `getHotSeatTopN` 写好了却没人能调 | 只有 service 方法、没有 HTTP 入口。属于「定义了却不用」——它给人"已经做完"的错觉 |
